# B-line history-memory training on 2×H200

This runbook packages and launches the two training arms defined by
`agent/train_history_memory.py`:

- **C**: the static history-memory view.
- **B**: the lifecycle-aware history-memory view built from the same decision
  manifest.

Each checkpoint mixes compression ratios 4 and 8. The four A0/A1 evaluation
combinations are evaluation conditions; they are not four training arms.

## 1. Package one committed source tree

Commit the intended source first. The package command reads Git objects from
that commit, so working-tree files are never copied accidentally.

```bash
python scripts/package_b_history.py \
  --commit HEAD \
  --output /tmp/c2kv-b-history.tar.gz
```

The archive excludes every tracked path under `data/`, `datasets/`, `models/`,
`checkpoints/`, `results/`, `outputs/`, and `secrets/`, together with common
credential files. `PACKAGE_MANIFEST.json` inside the archive records the full
source commit.

On the H200 host, extract it on the project mount and keep checkpoints on the
persistent global-user mount:

```bash
export B_REPO=/inspire/hdd/project/wuliqifa/yanjunchi-24040/yancheng/c2kv-b-history
export G_REPO=/inspire/hdd/project/wuliqifa/yanjunchi-24040/yancheng/c2kv
export GU_BASE=/inspire/hdd/global_user/yanjunchi-24040/yancheng_c2kv_h200
mkdir -p "${B_REPO}"
tar -xzf /path/to/c2kv-b-history.tar.gz -C "${B_REPO}" --strip-components=1
cd "${B_REPO}"
```

## 2. Create the isolated Python environment

The known G H200 environment used Python 3.12 with `torch 2.9.0+cu130` and
`transformers 5.8.0`. B uses a smaller environment pinned in
`requirements-b-history.txt`: `torch 2.9.0`, `transformers 5.8.0`,
`numpy 2.3.4`, `pyarrow 25.0.1`, `accelerate 1.14.0`, `wandb 0.29.0`, and
`pytest 9.1.1`. It uses plain PyTorch DDP and does not need DeepSpeed or
torchvision.

```bash
python3.12 -m venv .venv-b-history
source .venv-b-history/bin/activate
python -m pip install --upgrade pip
python -m pip install \
  --index-url https://download.pytorch.org/whl/cu130 \
  torch==2.9.0
python -m pip install -r requirements-b-history.txt
python - <<'PY'
import numpy, torch, transformers
print("torch", torch.__version__, "cuda", torch.version.cuda)
print("transformers", transformers.__version__, "numpy", numpy.__version__)
print("cuda_available", torch.cuda.is_available(), "gpus", torch.cuda.device_count())
PY
```

The launcher requires the base versions recorded above and checks that exactly
two H200 devices are visible by default. `flash_attn` is not required; `sdpa`
is the default attention implementation.

The base model remains frozen in BF16. Trainable gist parameters use FP32
master weights under autocast. Each `checkpoint-N` contains the full model and
tokenizer plus `optimizer.pt`, scheduler/RNG state, and the training contract;
resume restores the FP32 master weights directly instead of round-tripping
through BF16.

Before copying the 4B model or starting GPU work, run the real optimizer and
resume path with the built-in random tiny Qwen. This does not download a model:

```bash
export B_SMOKE_DIR="$(mktemp -d)"
.venv-b-history/bin/python agent/train_history_memory.py \
  --cpu_smoke --arm C --output_dir "${B_SMOKE_DIR}" \
  --save_steps 1 --stop_after_steps 1
.venv-b-history/bin/python agent/train_history_memory.py \
  --cpu_smoke --arm C --output_dir "${B_SMOKE_DIR}" \
  --save_steps 1 --resume_from_checkpoint "${B_SMOKE_DIR}/checkpoint-1"
```

Run this smoke from the extracted package as well. It verifies that the archive
contains `python/models`, `history_memory`, the trainer entry point, optimizer
state handling, and checkpoint resume.

## 3. Build and place the decision manifest

The training input is one bounded prepared-corpus directory consumed through
`--data_path`; it contains `manifest.json`, `sessions.jsonl`, and
`paired_decisions.jsonl`. Source archives intentionally exclude data.

CPU planning uses one process by default. `PREPARATION_WORKERS` in the wrapper,
or `--workers` on the Python entry point, selects the number of planning
processes. Each process advances a whole session in order; the parent consumes
sessions in their original order and applies the shared token caps. Worker
count controls execution resources and is not a sampling or training setting.

The G checkout fixes these existing H200 paths:

- traces: `${G_REPO}/datasets/agent-llm-traces`
- Toucan: `${G_REPO}/datasets/toucan`
- train split manifest:
  `${G_REPO}/outputs/agent_taskproxy_split_manifest.json`, split
  `taskproxy_disjoint`

G exposes Open-SWE, HotpotQA, 2Wiki, and LongMagpie only through environment
variables; its launcher does not fix their locations. Set those four paths to
the directories already used for the G preparation. Put them in the shared
environment file and inspect the resolved CPU-only command:

```bash
cp configs/b_history_h200.env.example configs/b_history_h200.env
# Edit OPENSWE_PATH and the three QA path variables in this private file.
bash agent/prepare_history_memory_h200.sh --dry-run
bash agent/prepare_history_memory_h200.sh
```

The builder emits JSON progress to stderr when the phase changes and at most
once every 30 seconds during decision processing. `decisions_visited` includes
unselected intermediate decisions because they advance B's lease state;
`paired_exposures_written` counts the accepted ratio/repetition pairs.
Preparation reuses immutable event tokenization within each session and exact
native prompt measurements within each decision. Sampling, budgets, C/B views,
and target construction are unchanged. A running Python process keeps its
loaded code: use the patched source for a new preparation invocation with the
same configuration. Do not overwrite a prepared corpus already used by training.

The wrapper validates the model, G sources, split manifest, Open-SWE, and at
least one configured QA source when `QA_TARGET_FRACTION` is positive. It never
downloads data or starts training. Its formal command expands to these builder
arguments:

```bash
export OPENSWE_PATH=/path/to/openswe
export QA_HOTPOTQA_PATH=/path/to/hotpotqa
export QA_2WIKI_PATH=/path/to/2wiki
export QA_LONGMAGPIE_PATH=/path/to/longmagpie

.venv-b-history/bin/python agent/build_history_memory_data.py \
  --output-dir "${GU_BASE}/data/b_history" \
  --model-name-or-path "${G_REPO}/models/Qwen3-4B-Instruct-2507" \
  --traces-path "${G_REPO}/datasets/agent-llm-traces" \
  --traces-split-manifest "${G_REPO}/outputs/agent_taskproxy_split_manifest.json" \
  --traces-split-name taskproxy_disjoint \
  --toucan-path "${G_REPO}/datasets/toucan" \
  --openswe-path "${OPENSWE_PATH}" \
  --hotpotqa-path "${QA_HOTPOTQA_PATH}" \
  --wiki2-path "${QA_2WIKI_PATH}" \
  --longmagpie-path "${QA_LONGMAGPIE_PATH}" \
  --qa-target-fraction 0.15 \
  --max-rows-per-source 50000 \
  --max-sessions 50000 \
  --max-decisions-per-session 64 \
  --max-total-decisions 100000 \
  --max-presented-tokens-per-arm 48000000 \
  --repetitions 1 --sampling-seed 42 \
  --ratios 4,8 \
  --max-chunk-tokens 768 --chunk-overlap 64 --max-chunks 48 \
  --max-encoder-tokens 36864 --max-system-tokens 8192 \
  --max-workspace-tokens 4096 --max-target-tokens 4096 \
  --max-sequence-tokens 16384 \
  --policy-mode persistent \
  --history-budget-bytes 2147483648 \
  --workspace-budget-bytes 536870912 \
  --lease-decisions 3 --max-retrieved-events 2
```

The traces adapter admits only the named training split and excludes any
benchmark name containing `airline`; other held-out `test`, `eval`, `dev`, or
`validation` sources are also excluded and counted in `manifest.json`. Corpus
preparation rejects a formal build when every B view equals C, or when every B
record has zero gist tokens and would give the compressor no B-arm gradient.
Inspect `changed_view_pairs`, `gist_bearing_pairs.arm.B`, the source audit,
tokenizer hash, paired arm identities, and presented-token totals before
launch. The prepared epoch is capped at 48M presented encoder tokens for each
arm, so the default two epochs expose at most 96M per arm. The manifest binds
both JSONL files by digest, so resume identity covers the full corpus rather
than the manifest filename alone. Do not train C and B from independently
sampled decision sets: record identities, split, order, exposure count, and
packing configuration must match.

## 4. Configure and inspect the launch

The same `configs/b_history_h200.env` file drives preparation and training. Its
defaults match the G H200 mount roots above. Review these resolved paths and
override them only if the host layout differs:

- `MODEL_NAME_OR_PATH`: defaults to the model under the existing G checkout.
- `DATA_PATH`: defaults to `${GU_BASE}/data/b_history`, the prepared-corpus
  directory above.
- `OUTPUT_BASE`: a directory on
  `/inspire/hdd/global_user/yanjunchi-24040/yancheng_c2kv_h200`.

Resolve the exact commands without importing Torch or touching the GPU:

```bash
bash agent/train_history_memory_h200.sh --dry-run
```

Run the full environment, model, data, dependency, GPU, and output-mount
preflight without training:

```bash
bash agent/train_history_memory_h200.sh --preflight-only
```

## 5. Run the matched training pair

The default command runs arm C and then arm B at seed 42. It uses 2 GPUs,
per-device batch 2, and gradient accumulation 8 for effective batch 32.

```bash
bash agent/train_history_memory_h200.sh
```

Run the formal paired seeds with the same configuration:

```bash
bash agent/train_history_memory_h200.sh --seeds "42 43 44"
```

Run one arm or seed explicitly:

```bash
bash agent/train_history_memory_h200.sh --arm C --seed 42
bash agent/train_history_memory_h200.sh --arm B --seed 42
```

Each run writes to `${OUTPUT_BASE}/arm-C/seed-N` or
`${OUTPUT_BASE}/arm-B/seed-N`. Ratios `4,8` are mixed within each run.

Resume only when you name the checkpoint for that arm:

```bash
bash agent/train_history_memory_h200.sh \
  --arm B --seed 42 \
  --resume-from-checkpoint /path/to/checkpoint
```

The launcher performs no automatic restart, fallback, pruning, evaluation,
process killing, or upload. To change attention, set `ATTN_IMPL=sdpa`,
`ATTN_IMPL=eager`, or `ATTN_IMPL=flex_attention` explicitly and treat the
choice as part of the run configuration.

W&B defaults to `offline`. Each run uses the project `c2kv-history-b`; set an
arm-specific `WANDB_RUN_ID_C` or `WANDB_RUN_ID_B` when resuming the matching
offline run. Set `WANDB_MODE=disabled` only for a bounded local smoke test.
